Tower of Hanoi — Theory & Implementation

How it works

Tower of Hanoi is a classic recursion problem with three pegs and disks of different sizes. The goal is to move the complete stack from the source peg to the destination peg while preserving the order of disk sizes.

Recursive strategy

  1. Move the top n − 1 disks from the source to the auxiliary peg.
  2. Move the largest disk from the source to the destination.
  3. Move the n − 1 disks from the auxiliary peg to the destination.

Rules

  • Move only one disk at a time.
  • Only the top disk of a peg may be moved.
  • A larger disk must never be placed on a smaller disk.

Where it is useful

Learning recursion, tracing the call stack, understanding divide-and-conquer style problem decomposition, recurrence relations, and analysing exponential algorithms.

When to be careful

The move count grows exponentially. Recursive code is elegant for explanation, but becomes impractical for large disk counts when every move must be displayed or executed.

RecursionBase case: n = 1Minimum moves: 2ⁿ − 1

Complexity & special cases

Best-case timeΘ(2ⁿ)
Average-case timeΘ(2ⁿ)
Worst-case timeΘ(2ⁿ)
Auxiliary spaceΘ(n)

The recurrence is T(n) = 2T(n − 1) + 1, with T(1) = 1. Solving it gives T(n) = 2ⁿ − 1 moves. The recursive call stack reaches a depth proportional to n.

Special cases
• For n = 0, no move is required (base case may return immediately).
• For n = 1, move the disk directly from source to destination.
• The standard three-peg puzzle has a proven minimum of 2ⁿ − 1 moves; this exact bound does not apply unchanged to variants with extra pegs or different rules.
• The interactive lab allows 3–8 disks; the code below accepts any non-negative n supported by the language's recursion and integer limits.
